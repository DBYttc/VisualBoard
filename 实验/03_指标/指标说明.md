# 指标说明（怎么算、怎么报）

> 报告里最容易被打回的两点：**wpm 没减 1**、**把 NCER 当成"准确率"**。照本文件的公式算就不会错。

## 一、指标定义

| 指标 | 公式 | 我们的数据从哪来 |
|---|---|---|
| 输入速度 **wpm** | `wpm = (目标字符数 − 1) / 输入时间(s) × 12` | 录屏时间轴 + `采集清单.csv` 的短语 |
| 最终字符错误率 **NCER** | `NCER = MSD / 目标字符数` | 对比"目标短语"与"实际输出" |
| 准确率 | `准确率 = 1 − NCER` | 同上 |
| 按下检出率 | `检出数 / (检出数 + 漏触数)` | `标注模板.csv` 的 press / missed |
| 误触率 | `false_trigger 次数 / 试次总时长(分钟)` | 同上 |
| 触发延迟 | `平均((字符出现帧 − 按下起始帧) / 实测FPS)` | 录屏逐帧 |
| 含纠正错误率 **TER**（可选） | 需要完整击键流（含退格） | 我们目前只能算 NCER；若要做，需在报告里说明"未统计纠正过程" |

### 为什么 wpm 要减 1

计时从**第一个字符落下**开始，那段时间只打出了 1 个字符，所以要扣掉；`×12` 是因为"一个词按 5 个字符算"：`60/5 = 12`。
（出处：MacKenzie, *A Note on Calculating Text Entry Speed*；变量名写 Entry Speed，单位写小写 `wpm`。）

## 二、MSD / NCER 怎么算（Excel 手算版）

MSD = **最小字符串距离**（Levenshtein 编辑距离）：把"实际输出"改成"目标短语"最少要多少次操作（插入 / 删除 / 替换）。

例子：目标 `the fox`，实际 `teh fox`
1. 对齐：`t e h _ f o x` vs `t e h _ f o x`… 逐字看，`e`/`h` 顺序不同 → 删除 1 次 + 插入 1 次（或替换 2 次，取更少的 2 次）
2. MSD = 2；目标字符数 = 7（含空格）→ `NCER = 2/7 ≈ 28.6%`，准确率 ≈ 71.4%

Excel 做法（不写代码）：
- 把"目标"和"实际"分别贴成两行字符（或用 `MID()` 逐字取出）
- 手工数"插入 / 删除 / 替换"的总次数，填进 `指标汇总表.csv` 的 `MSD合计`
- 想省事可在网上用 "Levenshtein distance calculator" 这类工具，但**把输入内容和结果截图存档**（证明是你算的）

## 三、要把哪些数据凑齐

一次"条件"（如 A2 基线）通常包含 N 个试次：

1. 目标字符数（固定短语，25）
2. 每次的输入时间（秒，从第一个字符到最后一个字符）
3. 每次的实际输出（屏幕上复制出来，或用日志里的 `Emitted key=` 序列还原）
4. 标注表里的 press / missed / false_trigger 区间数
5. 试次总时长（分钟，用于误触率）

**注意**：`Emitted key=` 的日志只能告诉你"出了什么"，不能告诉你"该不该出"——后者要靠标注表。

## 四、报告句式（直接改数字）

> 在 5 名被试、每人每条件 2 次的条件下，本系统平均输入速度为 **__ wpm**（标准差 __），最终字符错误率 **NCER = __%**，按下检出率 **__%**，误触率 **__ 次/分钟**，平均触发延迟 **__ ms**。
> 与文献中"纯空中虚拟键盘"的 12–20 wpm 区间处于同一量级；与"平面锚定 + 语言模型解码"的 37–42 wpm 的差距，主要来自**缺少接触面锚定**与**未使用语言模型纠错**，而非识别算法本身。

## 五、常见错误（自查）

- [ ] 开始计时的定义不一致（有人从"准备"开始算）→ 统一为"第一个字符落下"
- [ ] 用"字符正确数 / 总字符数"当准确率（会把顺序错误算成正确）→ 用 MSD
- [ ] 不同短语集的两组数据直接比 wpm（不可比）
- [ ] 中文经拼音输入法时**没把候选词选择算成操作**（会高估速度）
- [ ] 只报平均、不报标准差与人数
- [ ] 用"最好那次"当结果 → 报中位数或均值，并附全部原始数据
